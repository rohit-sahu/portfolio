# Docs Index

Which `.md` file to read for what.

| File | Read this when you want to... |
|---|---|
| [README.md](./README.md) | Get an overview of the project — what it is, its sections, tech stack, and how to start local dev. Start here. |
| [RUNNING.md](./RUNNING.md) | Run the app in **any** scenario — local dev, Docker locally, publishing to GHCR — as a quick-reference table, not a single linear path. TLS/reverse proxy/Cloudflare Tunnel are covered by a separate infra repo, not here. |
| [PRODUCTION_DEPLOYMENT.md](./PRODUCTION_DEPLOYMENT.md) | Follow a single, ordered checklist to go from a fresh server + domain to a live HTTPS site via Docker Compose (`deploy.sh`). The condensed, do-this-in-order version. |
| [DEPLOYMENT.md](./DEPLOYMENT.md) | Compare deployment **options** (Vercel vs. Docker/VPS vs. plain Node) before picking one, including env var differences between them. |
| [IMAGE_DEPLOYMENT_OPTIONS.md](./IMAGE_DEPLOYMENT_OPTIONS.md) | Decide how the `web` Docker image gets onto a server — build on the server, or pull a pre-built image from Docker Hub/GHCR/ECR/a transferred file. Referenced from the deploy step in `PRODUCTION_DEPLOYMENT.md`. |
| [SCRIPT_INPUTS.md](./SCRIPT_INPUTS.md) | Look up exactly how `publish-ghcr.sh`, `publish-ghcr 2.sh`, `deploy.sh`, and `deploy 2.sh` get their settings — CLI flags, environment variables, `.env`/`.env.local`/`.env.prod` files, and interactive prompts, with a full table of every setting each script accepts. Start here if a script errors out asking for a setting you don't know how to provide. |
| [AGENTS.md](./AGENTS.md) | Not for humans — auto-regenerated by `next dev` on every run with Next.js-version-specific agent instructions. Don't hand-edit; changes get overwritten. |
| [CLAUDE.md](./CLAUDE.md) | Not for humans — a one-line `@AGENTS.md` include so Claude-based tools pick up the same agent instructions. |

## Typical paths through these docs

- **First time setting up local dev:** README.md → RUNNING.md ("Local development" section).
- **Deploying to your own server for the first time:** PRODUCTION_DEPLOYMENT.md, referring out to IMAGE_DEPLOYMENT_OPTIONS.md at the image-build step. Fronting the app with a reverse proxy/TLS/Cloudflare Tunnel is handled by a separate infra repo, not this one.
- **Deciding where to host at all:** DEPLOYMENT.md.
- **Redeploying / changing how the image is built:** IMAGE_DEPLOYMENT_OPTIONS.md.
- **A script is asking for a setting and you're not sure how to provide it (flag, env var, or file):** SCRIPT_INPUTS.md.
